## Decisions
- D1: Base branch -> answer code-cleanup Q8 (A), finish that run, branch this plan from `orch/code-cleanup`.
- D2: Which rides get the Power Zone week relation -> every cycling ride (`_is_cycling_workout`), Peloton and outdoor Garmin.
- D3: Star handoff -> after the pipeline creates a new week page, every earlier PowerZone page whose icon is the emoji ⭐ gets the emoji ❓ (the owner picks the final icon by hand).
- D4: New week page -> Program Name = the PowerZone template's title; Week # = "Week N+1" where N is the highest `Week (\d+)` among pages with that Program Name, else "Week 1"; date range Monday to Sunday of the ride's week; icon and cover copied from the template; FTP copied from the most recent earlier page that has an FTP value; Weight (kg) left empty.
- D5: Manual edits win -> the icon and the `PowerZone [DB]` relation are written only when the page's current value is empty (on create and on update); a non-empty value is never changed.
- D6: Backfill -> after merge, one run of `sync_to_notion(since=2026-11-01)` on the Pi: icons on every Peloton ride since Nov 1; relations only where a covering week page exists or may be created under D7, so Nov 1-8 rides stay unlinked.
- D7 (owner confirmed assumption): A "Peloton ride" is a row where `determine_tag(row) == "Peloton Bike"`. A ride's week is computed from its America/Los_Angeles start date, not the UTC `workout_date`.
## Assumptions
- A1: "Create from the template" is done by reading the template page through the API (title, icon, cover) and creating a page with those values, not with Notion's template-apply API. The template body is empty, so nothing is lost; this needs no Notion-Version change.
- A2: A missing week page is created only when the ride's LA week start is later than the newest PowerZone page's week start. Rides in older weeks with no covering page stay unlinked and are logged. This stops a backfill from inventing past weeks.
- A3: The Peloton icon PNG is read from the template page on each process run (signed URL, downloaded, re-uploaded with the file-upload API already used at `notion_strava_sync.py:111`) and the template lookup is cached per process; one upload per page that needs an icon. If the template icon is an emoji, custom emoji or external URL, that icon object is copied as is.
- A4: Two rides synced back to back in one process must not create two week pages: a module-level cache `{week_start: page_id}` is checked before querying Notion and filled after a create (Notion's query index can lag a fresh page by seconds).
- A5: Icon and relation steps never fail the workout sync: each runs in its own try/except that logs a warning, like `poll_strava.py:231-236`. `NOTION_DRY_RUN=1` skips both.
- A6: The count-3 LESSONS line (spec-integrity re-spec) is a kit-repo change and stays out of scope, as in the code-cleanup plan.
