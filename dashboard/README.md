# Health dashboard

## Overview

A small Node 22 service (express + pg + echarts, no build step) that serves a
weight, nutrition and FTP dashboard, built to be embedded in Notion. It
replaces the Datawrapper charts: weight with 7-day average, daily calories,
daily protein, weekly goals met, today's calorie and protein rings, and FTP
and W/kg.

- `/d/<token>` the dashboard page; `?view=<name>` renders one panel.
- `/api/dashboard?range=7|30|90|365` JSON of daily aggregates (Bearer token).
- `/healthz` liveness, no auth.
- Reads Postgres as the read-only `dashboard_ro` role. ECharts is served from
  `/assets/vendor/`; no CDN, all assets from 'self'.

## Local preview

No database needed in demo mode (fake data):

```bash
cd dashboard
npm ci
DASHBOARD_DEMO=true DASHBOARD_TOKENS=$(node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))") npm start
```

Open `http://127.0.0.1:8878/d/<that token>?demo=1`. Add `?theme=dark` to test
dark mode. Tests: `npm test` (unit), `npm run test:integration` (needs a test
Postgres), `npm run check:compose`.

## Env vars

Read from `src/config.mjs`. The service refuses to start on an invalid value.

| Variable | Default | Required | Meaning |
|---|---|---|---|
| `DASHBOARD_TOKENS` | none | yes | Comma-separated access tokens, each at least 32 chars from `[A-Za-z0-9_-]`. The example placeholder is rejected on purpose. |
| `DB_PASSWORD` | none | yes, unless demo | Password of `dashboard_ro`. |
| `DB_HOST` | `localhost` | no | Postgres host (`127.0.0.1` in the example file). |
| `DB_PORT` | `5432` | no | Postgres port. |
| `DB_NAME` | `health_pi` | no | Database. |
| `DB_USER` | `dashboard_ro` | no | Login role. |
| `PORT` | `8878` | no | Listen port. |
| `HOST` | `127.0.0.1` | no | Bind address; keep loopback, the tunnel reaches it. |
| `FRAME_ANCESTORS` | `https://www.notion.so https://notion.so https://*.notion.site` | no | CSP `frame-ancestors` allow-list; space-separated, no quotes. |
| `PLAN_KG_PER_WEEK` | `0.75` | no | Planned loss rate, positive number, drawn as the plan line. |
| `PROTEIN_PCT_MIN` | `35` | no | Lower edge of the protein target band, % of daily calories (inclusive). |
| `PROTEIN_PCT_MAX` | `40` | no | Upper edge of the protein target band (inclusive). Both must be numbers with 0 <= min < max <= 100, otherwise the service refuses to start. |
| `DASHBOARD_DEMO` | unset | no | `true` serves fake data and needs no database. |
| `DASHBOARD_ENV_FILE` | `/home/mike/.config/health-dashboard/dashboard.env` | no | Compose only: path of the env file. |

Template: `dashboard.env.example`.

## Tokens

Generate one:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"
```

Put it in `DASHBOARD_TOKENS`. Several tokens may be listed, comma-separated.

Rotate a token (no downtime for readers who already updated):

1. Add the new token to `DASHBOARD_TOKENS` next to the old one (`old,new`).
2. From `dashboard/`, run the step 6 command of the Pi deploy runbook below (`up -d` recreates the container with the new env).
3. Update every Notion embed to the new token.
4. Remove the old token from `DASHBOARD_TOKENS`.
5. Recreate the container again the same way. The old URL now returns 404.

## Pi deploy runbook

Run on the Pi as `mike`, in order. Steps that run repo files come after the
`git pull` that puts them on the host. Repo path per `health-mcp/README.md`:
`/home/mike/projects/health-data-hub`.

1. Get the code.

   ```bash
   cd /home/mike/projects/health-data-hub
   git pull
   ```

2. Apply the role migration (it sets no password; it also needs the earlier
   migrations 00-02 already applied, see `docs/nutrition_deploy_runbook.md`).

   ```bash
   psql -U postgres -d health_pi -v ON_ERROR_STOP=1 --single-transaction \
     -f health_data_hub/db/migrations/2026-11_03_dashboard_role.sql
   ```

3. Set the role password (interactive; do not put it in shell history).

   ```bash
   psql -U postgres -d health_pi
   \password dashboard_ro
   ```

4. Allow the role over TCP in `pg_hba.conf` (find it with `sudo -u postgres psql -c 'SHOW hba_file'`), above any broader rule, then reload.

   ```
   host  health_pi  dashboard_ro  127.0.0.1/32  scram-sha-256
   ```

   ```bash
   sudo systemctl reload postgresql
   ```

5. Create the env file, outside git.

   ```bash
   mkdir -p ~/.config/health-dashboard
   cp dashboard/dashboard.env.example ~/.config/health-dashboard/dashboard.env
   chmod 600 ~/.config/health-dashboard/dashboard.env
   nano ~/.config/health-dashboard/dashboard.env   # set DASHBOARD_TOKENS and DB_PASSWORD
   ```

6. Build and start.

   ```bash
   cd dashboard
   docker compose up -d --build
   ```

7. Read-only checks (no side effects in production). `T` is one of your tokens.

   ```bash
   T=<token>
   curl -fsS http://127.0.0.1:8878/healthz
   curl -s -o /dev/null -w '%{http_code}' -H "Authorization: Bearer $T" 'http://127.0.0.1:8878/api/dashboard?range=7'
   ```

   Expect `ok` and `200`. If `/healthz` fails or the connection is
   refused, the container exited on the startup read-only/DB check: run
   `docker compose logs` and look for `Read-only check failed` (wrong
   `DB_PASSWORD`, missing `pg_hba` line, or migration not applied). A `503` from
   `/api/dashboard` means the database became unreachable or a query failed
   while the server was running. A `401` means the token is wrong.

8. Stop the Datawrapper jobs: restart the scheduler so it loads the code without them.

   ```bash
   sudo systemctl restart health-hub.service
   ```

   TODO: confirm the unit name on the Pi. `pi/README.md` says `health-hub.service`, the repo's unit file is `health-data-hub.service`.

9. Remove `DATAWRAPPER_API_TOKEN` from the Pi's `prod.env` (`health_data_hub/config/prod.env`), then restart the unit once more.

### Cloudflare Tunnel

The existing tunnel is `health-webhook` (`18a4d3ef-25b8-4989-b22f-3f42264c2d5e`), config in `/etc/cloudflared/config.yml`. Back it up, then add this rule above the catch-all (`http_status:404`) rule:

```yaml
ingress:
  # ...existing rules...
  - hostname: charts.michaelfigari.com
    service: http://localhost:8878
  - service: http_status:404   # catch-all stays last
```

```bash
sudo cp /etc/cloudflared/config.yml /etc/cloudflared/config.yml.bak-$(date +%s)
cloudflared tunnel route dns health-webhook charts.michaelfigari.com
sudo systemctl restart cloudflared.service
```

Check that the page is served with the CSP `frame-ancestors` and no `X-Frame-Options`:

```bash
curl -sI https://charts.michaelfigari.com/d/<token> | grep -i -E '^(HTTP|content-security-policy|x-frame-options)'
```

Expect `200`, a `content-security-policy` line containing `frame-ancestors https://www.notion.so ...`, and no `x-frame-options` line.

## Notion embed

In Notion type `/embed` and paste, for example:

```
https://charts.michaelfigari.com/d/<token>?view=weight
```

| View | URL suffix | Recommended height |
|---|---|---|
| Whole dashboard | (none) or `?view=all` | 1,600 px on desktop |
| Today (rings) | `?view=today` | 420-460 px |
| Weight + 7-day average | `?view=weight` | 420-460 px |
| Daily calories | `?view=calories` | 420-460 px |
| Daily protein | `?view=protein` | 420-460 px |
| Weekly goals met (calendar) | `?view=calendar` | 420-460 px |
| FTP and W/kg | `?view=ftp` | 420-460 px |

A Notion embed has one fixed height, so on phones prefer single views at 460 px
or less over the full dashboard.

## Theme

The page follows `prefers-color-scheme`. Override with `?theme=light` or
`?theme=dark`. Notion's own dark mode does not reach the iframe, so if Notion
is always dark, pin `?theme=dark` on every embed, e.g.
`.../d/<token>?view=weight&theme=dark`.

## Privacy notes

- The token is in the page URL. Anyone who can view the Notion page, and
  Cloudflare's request logs, can see it. Anyone holding it can read weight and
  intake. If a Notion page is shared, rotate the token (see Tokens).
- The API returns daily aggregates only (no workout titles, no food names, no raw samples).
- The database role is SELECT-only on five sources, read-only by default, 3 connections, 5 s statement timeout.
- No response bodies or queries are logged; the access log is one line per request (method, redacted path, status, time). Pages send `noindex` and `no-referrer`.
- Assets and the page are restricted by CSP to 'self'; framing is limited to `FRAME_ANCESTORS`.

## Rollback

```bash
cd /home/mike/projects/health-data-hub/dashboard
docker compose down
```

Then remove the `charts.michaelfigari.com` rule from `/etc/cloudflared/config.yml`,
restart `cloudflared.service` (remove the CNAME in the Cloudflare DNS tab if you
want it gone), and drop the role:

```bash
psql -U postgres -d health_pi -v ON_ERROR_STOP=1 --single-transaction \
  -f health_data_hub/db/migrations/2026-11_03_dashboard_role.down.sql
```

The Datawrapper jobs were removed in the same PR; `git revert` that PR to bring
them back. The published Datawrapper charts stay on datawrapper.de until you
delete them.
